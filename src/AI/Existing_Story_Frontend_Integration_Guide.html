Lưu ý quan trọng & Trạng thái Backend

Backend Luồng 2 (Existing Stories) đã được triển khai hoàn tất trên Backend! ExistingStoriesController đã hoạt động đầy đủ tại route /api/v1/stories. Backend hỗ trợ cả Nhập trực tiếp (JSON) và Upload File .txt / .docx (Multipart Form Data) lên đến 5 MB.
Base URL & Môi trường kết nối Backend lắng nghe qua CORS mở (cho phép mọi origin trong môi trường dev). Frontend cấu hình base URL trong tệp .env (ví dụ: VITE_API_URL=https://localhost:7001 hoặc http://localhost:5000). Mọi endpoint nghiệp vụ đều có tiền tố /api/v1/.
Điểm mấu chốt của Luồng B (Existing Story): Endpoint POST /existing/evaluate chỉ đánh giá safety và profile fit, trả về quyết định (Suitable, AdaptRecommended, Blocked). Nếu truyện đạt Suitable, frontend bắt buộc phải gọi POST /existing/keep-original để backend bàn giao sang chuỗi sinh học liệu (Vocabulary → Quiz → Discussion).

0. Xác thực & Chọn hồ sơ trẻ (Pre-requisites)

Trước khi người dùng thực hiện tạo câu chuyện (cả Luồng A và B), ứng dụng Frontend cần hoàn thành hai thao tác nền tảng:

0.1 Đăng nhập & Lưu giữ JWT Tokens

Endpoint đăng nhập hỗ trợ cả email lẫn username:

POST /api/v1/auth/login
Content-Type: application/json

{
  "usernameOrEmail": "parent@example.com",
  "password": "SecurePassword123!"
}

Response trả về cấu trúc token và thông tin người dùng:

{
  "success": true,
  "message": "Đăng nhập thành công.",
  "data": {
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "d8f1e2c3-...",
    "tokenType": "Bearer",
    "expiresInSeconds": 3600,
    "user": {
      "id": 15,
      "email": "parent@example.com",
      "fullName": "Nguyễn Văn A",
      "role": "Parent"
    },
    "mfaRequired": false
  },
  "errors": null
}

0.2 Làm mới token khi hết hạn (Refresh Token)

Khi nhận mã lỗi 401 Unauthorized từ bất kỳ API nào, frontend gọi endpoint sau để xoay vòng token mà không làm gián đoạn trải nghiệm người dùng:

POST /api/v1/auth/refresh-token
Content-Type: application/json

{
  "refreshToken": "d8f1e2c3-..."
}

0.3 Lấy danh sách hồ sơ trẻ (Child Profile Selection)

Cả hai luồng tạo truyện đều yêu cầu childProfileId hợp lệ để áp dụng đúng Safety Policy và Learning Profile của trẻ:

GET /api/v1/childprofile/mine
Authorization: Bearer <accessToken>

Frontend hiển thị dropdown hoặc thẻ chọn trẻ. Lưu childProfileId đang được chọn để gửi kèm vào payload tạo truyện.

1. Luồng tổng thể hai nhánh

Bước 1Chọn hồ sơ & Nguồn truyện
Bước 2Creative Input / Upload Story
Bước 3Safety Check / Evaluation
Bước 4Outline / Adapt Content
Bước 5Sinh học liệu (Vocab/Quiz/Disc)
Bước 6Review → Media → Ready

Tại Bước 3 của Luồng B (Tải truyện có sẵn), backend đưa ra 3 quyết định đánh giá:

Suitable

Nội dung hoàn toàn an toàn và phù hợp năng lực trẻ. Hiển thị nút “Sử dụng bản gốc”, gọi keep-original để tiến hành sinh học liệu.

AdaptRecommended

Nội dung an toàn nhưng từ vựng hoặc độ dài chưa khớp lứa tuổi. Cho phép chọn: AI Tinh chỉnh (Adapt), Sửa tay (Manual Edit), hoặc Giữ nguyên có lý do.

Blocked

Vi phạm chính sách an toàn nghiêm ngặt (Hard Safety). Không cho phép giữ nguyên hay tinh chỉnh. Chỉ hiển thị lỗi và nút “Lưu trữ” (Archive).

3. Quy ước Request & Response

Mọi request (ngoại trừ các endpoint public như Login/Register) phải đính kèm Header xác thực:

Authorization: Bearer <accessToken>
Accept: application/json

3.1 Định dạng phản hồi Envelope chuẩn

Mọi API đều trả về cấu trúc bọc dữ liệu đồng nhất:

{
  "success": true,
  "message": "Thao tác thành công.",
  "data": { ... },
  "errors": null
}

Khi có lỗi (4xx / 5xx), envelope vẫn giữ nguyên định dạng:

{
  "success": false,
  "message": "Dữ liệu đầu vào không hợp lệ.",
  "data": null,
  "errors": [
    "Nội dung truyện vượt quá giới hạn 200000 ký tự."
  ]
}
Lưu ý quan trọng cho Frontend Client: Luôn trích xuất dữ liệu từ trường response.data.data (hoặc envelope.data). Không đọc trực tiếp từ tầng gốc của JSON response.

6. Luồng A — Tạo câu chuyện bằng AI

6.1 Tải context cấu hình trước khi render Form

GET /api/v1/ai-story-input/children/{childProfileId}/context

Sử dụng dữ liệu trả về để khởi tạo các trường: maximumLength, ngôn ngữ mặc định, các mức availableVocabularyLevels (level_1 đến level_5), và gợi ý sở thích (interests). Tránh hard-code trên Frontend.

6.2 Gửi yêu cầu sáng tác truyện (Submit Request)

POST /api/v1/ai-story-input/requests
Content-Type: application/json

{
  "childProfileId": 42,
  "topic": "Chuyến thám hiểm khu rừng đom đóm",
  "genre": "Phiêu lưu, Giả tưởng",
  "characterMode": "specified",
  "characters": ["Bé An", "Sóc Nâu"],
  "settingMode": "specified",
  "setting": "Khu rừng nhiệt đới vào buổi hoàng hôn",
  "lesson": "Lòng dũng cảm và tinh thần đồng đội",
  "vocabularyLevel": "level_2",
  "language": "vi",
  "targetLength": 600,
  "idempotencyKey": "ai-req-42-b892a014-9988-4c12"
}

Backend trả về HTTP 202 Accepted. Frontend lưu storyId và requestId để polling kiểm tra:

GET /api/v1/ai-story-input/stories/{storyId}/requests/{requestId}

Khi inputStatus === 'input_accepted', lập tức điều hướng sang màn hình theo dõi Dàn ý (Outline).

6.3 Polling & Duyệt Dàn ý (Outline)

GET /api/v1/stories/{storyId}/outline

Khi currentVersion có dữ liệu, hiển thị 3 phần: Mở đầu (Opening), Diễn biến (Development), Kết thúc (Ending). Người dùng có các lựa chọn:

  • Chỉnh sửa trực tiếp: Gọi PUT /api/v1/stories/{storyId}/outline/versions/{versionNo}.
  • Yêu cầu AI sinh lại: Gọi POST /api/v1/stories/{storyId}/outline/versions/{versionNo}/regenerate kèm operationKey.
  • Phê duyệt: Gọi POST /api/v1/stories/{storyId}/outline/versions/{versionNo}/approve kèm approvalKey. Bất kỳ tài khoản Parent hoặc Teacher đang quản lý hồ sơ trẻ (Supervision Relationship) đều có quyền duyệt mà không cần cấp quyền chi tiết. Sau khi duyệt, backend tự động khởi động quy trình sinh toàn văn nội dung và học liệu (Phase 3).

7. Luồng B — Tải truyện có sẵn (Paste / TXT / DOCX)

7.1 Lựa chọn 1: Upload File trực tiếp bằng FormData (Khuyên dùng)

Dành cho trường hợp người dùng bấm chọn tệp từ máy tính (hỗ trợ cả .txt UTF-8 và .docx Word, dung lượng tối đa 5 MB):

POST /api/v1/stories/import-file
Content-Type: multipart/form-data (trình duyệt tự gắn kèm boundary)

Form Fields:
- File: (tệp nhị phân .txt hoặc .docx)
- Title: "Chú bé chăn cừu"
- ChildProfileId: 42
- Language: "vi"
- IdempotencyKey: "import-file-42-abc12345"

7.2 Lựa chọn 2: Nhập văn bản thô dạng JSON

Dành cho trường hợp người dùng copy/paste vào Textarea:

POST /api/v1/stories/import
Content-Type: application/json

10. Mã nguồn API Client mẫu (TypeScript + Fetch)

services/api-client.ts
const BASE_URL = import.meta.env.VITE_API_URL || 'https://localhost:7001';

export class ApiError extends Error {
  constructor(
    public status: number,
    message: string,
    public errors: string[] = [],
    public data: any = null,
  ) {
    super(message);
    this.name = 'ApiError';
  }
}

// Lưu trữ token trong Memory hoặc LocalStorage/Secure Cookie
let accessToken: string | null = localStorage.getItem('access_token');
let refreshToken: string | null = localStorage.getItem('refresh_token');

export function setTokens(access: string, refresh: string) {
  accessToken = access;
  refreshToken = refresh;
  localStorage.setItem('access_token', access);
  localStorage.setItem('refresh_token', refresh);
}

export function clearTokens() {
  accessToken = null;
  refreshToken = null;
  localStorage.removeItem('access_token');
  localStorage.removeItem('refresh_token');
}

// Fetch wrapper có cơ chế tự động Refresh Token khi gặp lỗi 401
export async function request<T>(
  endpoint: string,
  options: RequestInit = {},
  isRetry = false
): Promise<T> {
  const isFormData = options.body instanceof FormData;
  const headers: Record<string, string> = {
    Accept: 'application/json',
    ...(isFormData ? {} : { 'Content-Type': 'application/json' }),
    ...(options.headers as Record<string, string>),
  };

  if (accessToken) {
    headers['Authorization'] = `Bearer ${accessToken}`;
  }

  const response = await fetch(`${BASE_URL}${endpoint}`, {
    ...options,
    headers,
  });

  // Tự động xoay vòng Token nếu gặp 401 Unauthorized
  if (response.status === 401 && !isRetry && refreshToken) {
    try {
      const refreshRes = await fetch(`${BASE_URL}/api/v1/auth/refresh-token`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ refreshToken }),
      });
      const refreshEnvelope = await refreshRes.json();
      if (refreshRes.ok && refreshEnvelope.success) {
        setTokens(refreshEnvelope.data.accessToken, refreshEnvelope.data.refreshToken);
        return request<T>(endpoint, options, true); // Replay request
      }
    } catch {
      clearTokens();
      window.location.href = '/login';
    }
  }

  const envelope = await response.json();
  if (!response.ok || !envelope.success) {
    throw new ApiError(
      response.status,
      envelope.message || 'Yêu cầu thất bại.',
      envelope.errors || [],
      envelope.data
    );
  }

  return envelope.data as T;
}

import { request } from './api-client';
import type {
  ImportStoryJsonRequest,
  ImportStoryResult,
  ExistingStoryEvaluation,
  VersionMutationResult,
  ContentGenerationProgress,
} from '../types/story-api';

export const existingStoryApi = {
  // 1. Upload File (.txt hoặc .docx) qua FormData
  importFile: (file: File, childProfileId: number, title?: string) => {
    const formData = new FormData();
    formData.append('File', file);
    formData.append('ChildProfileId', childProfileId.toString());
    formData.append('Language', 'vi');
    if (title) formData.append('Title', title);
    formData.append('IdempotencyKey', `file-${Date.now()}-${Math.random().toString(36).substring(2, 9)}`);

    return request<ImportStoryResult>('/api/v1/stories/import-file', {
      method: 'POST',
      body: formData,
    });
  },

  // 2. Nhập text paste qua JSON
  importJson: (payload: ImportStoryJsonRequest) =>
    request<ImportStoryResult>('/api/v1/stories/import', {
      method: 'POST',
      body: JSON.stringify(payload),
    }),

  // 3. Đánh giá truyện
  evaluate: (storyId: number, storyVersionId: number) =>
    request<ExistingStoryEvaluation>(`/api/v1/stories/${storyId}/existing/evaluate`, {
      method: 'POST',

    }),

11. SignalR Realtime Hub (Thông báo thời gian thực)

Hệ thống cung cấp SignalR Hub tại địa chỉ /hubs/notifications để thông báo trạng thái nền (như khi truyện đã hoàn tất Media, hoặc kiểm tra an toàn xong):

services/signalr.ts
import * as signalR from '@microsoft/signalr';

let connection: signalR.HubConnection | null = null;

export function initNotificationHub(onNotificationReceived: (notification: any) => void) {
  const token = localStorage.getItem('access_token');
  if (!token) return;

  connection = new signalR.HubConnectionBuilder()
    .withUrl(`${import.meta.env.VITE_API_URL || 'https://localhost:7001'}/hubs/notifications`, {
      accessTokenFactory: () => localStorage.getItem('access_token') || '',
    })
    .withAutomaticReconnect()
    .build();

  connection.on('ReceiveNotification', (notification) => {
    console.log('Realtime notification received:', notification);
    onNotificationReceived(notification);
  });

  connection.start().catch((err) => console.error('SignalR Connection Error: ', err));
}

export function stopNotificationHub() {
  if (connection) {
    connection.stop();
  }
}

14. Checklist nghiệm thu kết nối Frontend

  • Đã cấu hình đúng VITE_API_URL trong môi trường Frontend.
  • Mọi request bảo vệ đều gửi đúng Header Authorization: Bearer <token>.
  • Fetch interceptor tự động refresh token khi gặp 401 mà không làm mất trạng thái form.
  • Upload file .txt và .docx hoạt động mượt mà qua endpoint /import-file không tự set header Content-Type.
  • Paste text hoạt động chuẩn xác qua /import với inputMethod: 'paste'.
  • Đã kiểm tra xử lý cả 3 nhánh đánh giá: Suitable, AdaptRecommended và Blocked.
  • Nhánh Suitable gọi thành công POST /existing/keep-original trước khi vào polling học liệu.
  • Nhánh Blocked khóa toàn bộ nút giữ nguyên/sửa, chỉ hiển thị lý do và nút Lưu trữ.
  • Màn hình Review Package tải đủ 4 thành phần: Story, Vocabulary, Quiz và Discussion.
  • Nút Phê duyệt chỉ kích hoạt sau khi gọi GET /review/validation trả về canApprove: true.
  • Polling Media dừng chuẩn xác khi isReady === true và mở giao diện đọc truyện cho trẻ.

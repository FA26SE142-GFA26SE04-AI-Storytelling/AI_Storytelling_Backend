API và test case — TÊN CHỨC NĂNG

AI Storytelling Backend · mô tả ngắn phạm vi · mỗi API có giải thích, body mẫu và test case kèm đầu vào / kết quả mong đợi. Tích vào ô để đánh dấu đã chạy (lưu trong trình duyệt).

Quy ước chung

Cách gọi

  • Địa chỉ gốc: {host}/api/v1/{Controller}. Phản hồi bọc trong ApiResponse: { "success", "message", "data", "errors" }.
  • Đính kèm Authorization: Bearer {accessToken}. Token trẻ chỉ dùng được cho API đánh dấu ChildSession.
  • Lỗi nghiệp vụ: { "success": false, "message": "…", "data": null }. Sai kiểu dữ liệu: 400 "Dữ liệu đầu vào không hợp lệ." kèm errors. Sai vai trò: 403 body rỗng; không có token: 401.
  • Mã lỗi: 400 sai dữ liệu, 401 chưa đăng nhập, 403 sai vai trò / không có quyền, 404 không có, 409 xung đột trạng thái.
  • Enum gửi dạng chuỗi (ghi rõ các giá trị hợp lệ ở đây).

Dữ liệu thật trong Database/Seed (nạp bằng Seed-Database.ps1)

  • Trước hết: áp migration cần thiết (nếu có), rồi chạy Database/Seed-Database.ps1.
  • Mật khẩu mọi tài khoản demo: Demo@123. Đăng nhập bằng POST /api/v1/Auth/login với { "identifier": "tên-đăng-nhập", "password": "Demo@123" }.
  • Tài khoản dùng trong trang: (liệt kê username, id, role, dữ liệu liên quan).
  • Dữ liệu seed liên quan: (liệt kê bảng / id / trạng thái ban đầu mà kết quả mong đợi dựa vào).
  • Id kế tiếp trên DB mới seed: (để điền mặc định cho giá trị động).
  • Lưu ý: test làm đổi dữ liệu. Ghi rõ: mỗi Task bắt đầu từ DB vừa seed, chạy theo thứ tự trên trang.
Danh sách các bước / Task và nguồn (spec, plan). Mục có nhãn SQL là kiểm tra trực tiếp trên database / tài liệu, không gọi API.

0. Xác thực & Chọn hồ sơ trẻ (Pre-requisites)

Cả 2 trường hợp tạo câu chuyện đều bắt buộc phải đính kèm Header xác thực của tài khoản Phụ huynh hoặc Giáo viên (Parent hoặc Teacher), và xác định rõ childProfileId của trẻ để Backend áp dụng đúng Chính sách an toàn (SafetyPolicy) và Hồ sơ năng lực (LearningProfile).

0.1 Đăng nhập & Nhận JWT Bearer Token POST /api/v1/auth/login

Request Body (JSON):

{
  "usernameOrEmail": "parent1@example.com",
  "password": "Demo@123"
}
Hoạt động phía Backend: Backend xác thực thông tin tài khoản, kiểm tra vai trò (Role: Parent/Teacher/Admin). Nếu chính xác, cấp phát cặp accessToken (thời hạn 1 giờ) và refreshToken (thời hạn 7 ngày).

Lưu ý Frontend: Lưu accessToken vào Memory/Cookie và tự động đính kèm vào Header của mọi request kế tiếp: Authorization: Bearer <accessToken>.

0.2 Lấy danh sách hồ sơ trẻ (Child Profiles) GET /api/v1/childprofile/mine
Hoạt động phía Backend: Backend truy vấn bảng child_profiles dựa trên OwnerUserId hoặc quan hệ giám sát supervision_relationships của tài khoản đang đăng nhập, trả về danh sách các bé cùng độ tuổi (ageBand) và trình độ đọc (readingLevel).

Lưu ý Frontend: Dựng Dropdown/Modal cho người dùng chọn bé sẽ đọc truyện này, lấy ra childProfileId để truyền vào các bước tạo truyện tiếp theo.

1. So sánh tổng quan hai trường hợp (Luồng A vs Luồng B)

Tiêu chí so sánh Trường hợp 1: Luồng A (AI Sáng tác mới) Trường hợp 2: Luồng B (Nhập truyện có sẵn)
Nguồn truyện (Source) Ai (AI tự sáng tác) Manual (Người dùng cung cấp)
Dữ liệu đầu vào từ FE Chủ đề, thể loại, nhân vật, bối cảnh, bài học, độ dài mục tiêu. Paste văn bản thô trực tiếp hoặc Upload tệp .txt / .docx.
Kiểm tra an toàn ban đầu Input Guardrail: Quét prompt/ý tưởng chống từ khóa bạo lực, 18+, độc hại. Full Content Guardrail: Quét toàn bộ nội dung văn bản gốc theo Safety Policy.
Giai đoạn Dàn ý (Outline) Bắt buộc: AI tạo dàn ý 3 hồi (Mở đầu, Diễn biến, Kết thúc) ➡️ Người dùng xem, sửa hoặc duyệt. Bỏ qua hoàn toàn: Vì truyện đã có sẵn toàn văn cốt truyện, không cần sinh dàn ý.
Đánh giá độ phù hợp (Evaluation) Tự động cân chỉnh theo mức từ vựng mục tiêu (level_1 đến level_5). Thuật toán FKGL & FRE: Đo độ khó, an toàn, đưa ra 3 nhánh: Suitable, AdaptRecommended, Blocked.
Hình thành câu chuyện AI tự động viết toàn văn câu chuyện theo Dàn ý đã duyệt. Dùng bản gốc (Keep Original), nhờ AI viết lại (Adapt), hoặc tự biên tập (Manual Edit).
Giai đoạn Hội tụ (Phần 4) HỘI TỤ HOÀN TOÀN: Sinh Từ vựng (Vocabulary) ➔ Trắc nghiệm (Quiz) ➔ Thảo luận (Discussion) ➔ Phê duyệt (Approve) ➔ Sinh Media (Ảnh + Giọng đọc TTS).

2. Trường hợp 1: Sáng tác câu chuyện hoàn toàn bằng AI (Luồng A)

Áp dụng khi phụ huynh hoặc giáo viên muốn AI tự động sáng tác một câu chuyện hoàn toàn mới từ ý tưởng, bài học đạo đức và nhân vật được gợi ý.

Bước A1: Lấy Context cấu hình trước khi render Form GET /api/v1/ai-story-input/children/{childProfileId}/context
Hoạt động phía Backend: Backend đọc thông tin ChildProfile, LearningProfile (độ tuổi, trình độ đọc, sở thích) và SafetyPolicy (độ dài tối đa, các mức từ vựng cho phép) để trả về cấu hình an toàn cho Form sáng tác.

Response mẫu (`200 OK`):

{
  "success": true,
  "data": {
    "childProfileId": 1,
    "childNickname": "Bé An",
    "ageBand": "6-8",
    "readingLevel": 2,
    "defaultVocabularyLevel": "level_2",
    "availableVocabularyLevels": ["level_1", "level_2", "level_3"],
    "defaultLanguage": "vi",
    "maximumLength": 800,
    "interests": ["Khủng long", "Thám hiểm", "Động vật rừng"]
  }
}

Lưu ý Frontend: Dùng các giá trị này để thiết lập Dropdown mức từ vựng, placeholder gợi ý chủ đề và giới hạn độ dài (max characters/words) trên UI.

Bước A2: Gửi ý tưởng tạo truyện (Submit Creative Input) POST /api/v1/ai-story-input/requests

Request Body (JSON):

{
  "childProfileId": 1,
  "topic": "Chuyến phiêu lưu tìm quả hạt dẻ vàng",
  "genre": "Phiêu lưu, Cổ tích",
  "characterMode": "specified",
  "characters": ["Sóc Bông", "Thỏ Trắng"],
  "settingMode": "specified",
  "setting": "Khu rừng dẻ vào mùa thu",
  "lesson": "Biết chia sẻ niềm vui và sự giúp đỡ với bạn bè",
  "vocabularyLevel": "level_2",
  "language": "vi",
  "targetLength": 500,
  "idempotencyKey": "ai-req-child1-uuid-001"
}
Hoạt động phía Backend: 1. Backend tạo một bản ghi Story mới với trạng thái Draft, nguồn Source = Ai.
2. Tạo bản ghi StoryGenerationRequest với trạng thái CheckingInput.
3. Kích hoạt bộ kiểm duyệt an toàn đầu vào (Input Guardrail) để phát hiện từ ngữ nhạy cảm hoặc không phù hợp trẻ em.

Response mẫu (`202 Accepted`):

{
  "success": true,
  "data": {
    "storyId": 25,
    "requestId": 142,
    "inputStatus": "checking_input",
    "canRetry": false
  },
  "message": "Yêu cầu sáng tác đã được tiếp nhận."
}

Lưu ý Frontend: Lưu lại storyId = 25 và requestId = 142 để chuyển sang bước kiểm tra kết quả Guardrail.

Bước A3: Polling kiểm tra Guardrail Input GET /api/v1/ai-story-input/stories/{storyId}/requests/{requestId}
Hoạt động phía Backend: Trả về trạng thái xử lý của Input Guardrail. Có 3 trạng thái khả dĩ:
- checking_input: Đang phân tích nội dung.
- input_accepted: Đã duyệt an toàn, Backend tự động kích hoạt tiến trình sinh Dàn ý.
- input_blocked: Bị chặn do vi phạm chính sách an toàn (chứa từ khóa cấm).

Lưu ý Frontend: Polling mỗi 1.5 - 2 giây. Khi inputStatus === 'input_accepted', lập tức chuyển người dùng sang Bước A4 (Màn hình Dàn ý).

Bước A4: Nhận Dàn ý 3 hồi do AI sinh (Get Outline) GET /api/v1/stories/{storyId}/outline
Hoạt động phía Backend: AI Service đã chia câu chuyện thành 3 phần rõ ràng: Mở đầu (Opening), Diễn biến (Development), và Kết thúc (Ending), lưu trong story_versions với VersionNo = 1.

Response mẫu (`200 OK`):

{
  "success": true,
  "data": {
    "storyId": 25,
    "storyStatus": "Draft",
    "currentVersion": {
      "id": 45,
      "versionNo": 1,
      "title": "Sóc Bông và Những Quả Hạt Dẻ Vàng",
      "opening": "Một buổi sáng mùa thu mát mẻ, chú Sóc Bông đi vào rừng dẻ...",
      "development": "Sóc Bông tìm thấy gốc cây cổ thụ đầy hạt dẻ vàng nhưng gặp bạn Thỏ đang đói bụng...",
      "ending": "Sóc Bông chia sẻ hạt dẻ cho Thỏ, hai bạn cùng vui vẻ dưới nắng ấm.",
      "isCurrent": true,
      "outlineApprovedAt": null
    }
  }
}
Bước A5 (Tùy chọn): Chỉnh sửa hoặc Yêu cầu AI sinh lại Dàn ý PUT /api/v1/stories/{storyId}/outline/versions/{versionNo}

Nếu người dùng muốn sửa lại cốt truyện trước khi sinh toàn văn:

  • Sửa trực tiếp bằng tay: Gọi PUT /api/v1/stories/{storyId}/outline/versions/{versionNo} kèm body { title, opening, development, ending }. Backend tạo Version mới với EditType = HumanEdited.
  • Yêu cầu AI sinh lại: Gọi POST /api/v1/stories/{storyId}/outline/versions/{versionNo}/regenerate. Backend gọi AI sinh ra Dàn ý mới với EditType = AiRefined.
Bước A6: Phê duyệt Dàn ý & Kích hoạt sinh toàn văn (Approve Outline) POST /api/v1/stories/{storyId}/outline/versions/{versionNo}/approve
Hoạt động phía Backend: 1. Backend đóng băng Dàn ý (ghi nhận OutlineApprovedAt).
2. Tự động khởi tạo Background Job GenerateContent để AI viết toàn bộ câu chuyện chi tiết.
3. Ngay sau khi câu chuyện viết xong, Backend tự động nối tiếp chuỗi sinh học liệu Phase 3 (Từ vựng ➔ Trắc nghiệm ➔ Thảo luận).

Lưu ý Frontend: Sau khi bấm Duyệt, chuyển ngay sang màn hình Giai đoạn hội tụ chung (Bước C1: Polling sinh học liệu).

3. Trường hợp 2: Nhập hoặc Tải câu chuyện có sẵn (Luồng B)

Áp dụng khi phụ huynh hoặc giáo viên đã có sẵn một câu chuyện từ sách giáo khoa, truyện cổ tích hoặc tài liệu văn bản bên ngoài và muốn tải lên hệ thống để đánh giá, chuyển thể và sinh học liệu.

Bước B1: Tiếp nhận truyện (Chọn 1 trong 2 hình thức: File hoặc Paste) POST /api/v1/stories/import-file & /import

Cách 1: Upload File trực tiếp (Khuyên dùng khi chọn tệp .txt / .docx)

Gửi request dạng Multipart/Form-Data lên endpoint /api/v1/stories/import-file:

POST /api/v1/stories/import-file
Content-Type: multipart/form-data

Form Data Fields:
- File: [File nhị phân .txt hoặc .docx, tối đa 5 MB]
- Title: "Sóc Bông và Những Quả Hạt Dẻ Vàng"
- ChildProfileId: 1
- Language: "vi"
- IdempotencyKey: "import-file-001"

Cách 2: Nhập văn bản thô dạng JSON (Dành cho việc copy/paste vào Textarea)

Gửi request dạng Application/JSON lên endpoint /api/v1/stories/import:

POST /api/v1/stories/import
Content-Type: application/json

{
  "childProfileId": 1,
  "inputMethod": "paste",
  "title": "Sóc Bông và Những Quả Hạt Dẻ Vàng",
  "content": "Một buổi sáng mùa thu trời trong vắt, chú Sóc Bông khoác áo ấm đi vào rừng dẻ. Dưới gốc cây cổ thụ, Sóc Bông tìm thấy những quả hạt dẻ vàng thơm ngon. Chú nhặt đầy túi mang về chia cho bạn Thỏ và bạn Nhím cùng ăn.",
  "language": "vi",
  "idempotencyKey": "import-paste-001"
}
Hoạt động phía Backend (Rất quan trọng): 1. Chuẩn hóa văn bản: StoryContentNormalizer tự động dọn dẹp khoảng trắng dư thừa, chuẩn hóa ký tự xuống dòng.
2. Xác thực bảo vệ: Kiểm tra quyền quản lý hồ sơ trẻ (ISupervisionAccessGuard). Nếu không có quyền, trả về lỗi 403 Forbidden.
3. Kiểm tra ngôn ngữ & độ dài: So sánh với SafetyPolicy của trẻ. Nếu vượt quá độ dài tối đa (Maximum Story Length), trả về 400 Bad Request.
4. Full Content Guardrail: Quét các từ ngữ cấm (bạo lực, người lớn...). Nếu vi phạm, lưu truyện nhưng đánh dấu canProceed = false và inputStatus = "input_blocked".
5. Chống trùng lặp (Idempotency): Nếu gửi lại cùng idempotencyKey, Backend trả về ngay storyId cũ mà không sinh bản ghi trùng.
6. Lưu trữ bản gốc: Tạo bản ghi Story (Draft, Source = Manual) và StoryVersion (Version 1, EditType = Initial, IsCurrent = true).

Response mẫu (`200 OK`):

{
  "success": true,
  "data": {
    "storyId": 21,
    "storyVersionId": 27,
    "storyStatus": "Draft",
    "editType": "Initial",
    "canProceed": true,
    "inputStatus": "input_accepted",
    "warnings": []
  },
  "message": "Import truyện thành công."
}

Lưu ý Frontend: Lưu lại storyId = 21 và storyVersionId = 27. Nếu canProceed === true, chuyển ngay sang Bước B2 (Đánh giá).

Bước B2: Đánh giá chất lượng, độ tuổi & an toàn (Evaluate Story) POST /api/v1/stories/{storyId}/existing/evaluate

Request Body (JSON):

{
  "storyVersionId": 27
}
Hoạt động phía Backend: Backend chạy thuật toán thẩm định chuyên sâu dành riêng cho văn bản tiếng Việt tiểu học:
- Chỉ số FKGL (Flesch-Kincaid Grade Level): Đo độ khó của câu theo khối lớp học.
- Chỉ số FRE (Flesch Reading Ease): Đo độ dễ hiểu (thang điểm 0 - 100).
- Safety Score: Điểm an toàn dựa trên danh mục chính sách phụ huynh cài đặt.
- Quyết định (Decision): Tổng hợp để đưa ra 1 trong 3 trạng thái: Suitable, AdaptRecommended hoặc Blocked. Kết quả này được tự động lưu vào Cache để tải nhanh qua GET /api/v1/stories/{storyId}/existing/evaluation.

Response mẫu (`200 OK`):

{
  "success": true,
  "data": {
    "storyId": 21,
    "storyVersionId": 27,
    "decision": 1,
    "decisionText": "Suitable",
    "safetyScore": 1.0,
    "readabilityFkgl": 2.4,
    "readabilityFre": 85.0,
    "canKeepOriginal": true,
    "hardSafetyIssues": [],
    "profileFitIssues": []
  },
  "message": "Đánh giá truyện hoàn tất."
}
Bước B3: Xử lý 3 nhánh quyết định trên giao diện Frontend Decision Branching

Dựa vào trường decisionText từ Bước B2, Frontend hiển thị giao diện tương ứng theo 3 nhánh:

Nhánh 1: Suitable (Đạt chuẩn)

Nội dung hoàn toàn phù hợp với độ tuổi và an toàn. Nút hành động chính là "Sử dụng bản gốc".

Nhánh 2: AdaptRecommended

Nội dung an toàn nhưng câu văn quá dài hoặc từ vựng khó so với bé. Cung cấp 3 nút: AI Tinh chỉnh, Tự sửa tay hoặc Giữ nguyên.

Nhánh 3: Blocked (Bị chặn)

Vi phạm an toàn nghiêm trọng (bạo lực, nhạy cảm). Khóa toàn bộ các nút tiếp tục, chỉ hiển thị nút "Lưu trữ".

Chi tiết cách gọi API cho từng nhánh:

🔹 Lựa chọn 1: Giữ nguyên bản gốc (Keep Original)

Áp dụng khi đạt Suitable hoặc khi phụ huynh đồng ý giữ nguyên bản gốc dù có cảnh báo:

POST /api/v1/stories/21/existing/keep-original
{
  "storyId": 21,
  "storyVersionId": 27,
  "overrideReason": "Phụ huynh đồng ý giữ nguyên vẹn lời văn gốc cho bé."
}
Hoạt động phía Backend: Backend chốt phiên bản hiện tại, tự động bàn giao (Handoff) sang chuỗi sinh học liệu Phase 3 (tạo Job GenerateVocabulary).

🔹 Lựa chọn 2: Nhờ AI chuyển thể câu chuyện (AI Adapt)

Áp dụng khi câu chuyện quá dài hoặc từ ngữ khó, nhờ AI đơn giản hoá theo lứa tuổi của trẻ:

POST /api/v1/stories/21/existing/adapt
{
  "storyId": 21,
  "baseStoryVersionId": 27,
  "guideline": "Hãy viết lại câu chuyện bằng câu từ ngắn gọn, dễ hiểu hơn dành cho bé 6 tuổi."
}
Hoạt động phía Backend: 1. Backend giữ nguyên Version 27 (Initial, IsCurrent = false) để làm Audit Trail bảo tồn bản gốc.
2. Gọi AI tinh chỉnh lại câu chuyện và rút ra bài học đạo đức.
3. Tạo phiên bản mới Version 28 (EditType = AiRefined, IsCurrent = true).
4. Tự động đánh giá lại Version mới. Nếu đạt Suitable, tự động bàn giao sang Phase 3. Nếu là AdaptRecommended, chờ phụ huynh duyệt lại.

🔹 Lựa chọn 3: Phụ huynh tự chỉnh sửa thủ công (Manual Edit)

PUT /api/v1/stories/21/existing/content
{
  "storyId": 21,
  "baseStoryVersionId": 27,
  "title": "Sóc Bông và Quả Hạt Dẻ Vàng (Bản sửa)",
  "content": "Một buổi sáng mùa thu mát mẻ, chú Sóc Bông đi vào rừng dẻ...",
  "lesson": "Biết chia sẻ niềm vui và đồ ăn với bạn bè."
}
Hoạt động phía Backend: Tạo phiên bản mới với EditType = HumanEdited, giữ nguyên bản gốc không bị ghi đè.

🔹 Lựa chọn 4: Lưu trữ câu chuyện (Archive) khi bị Blocked hoặc hủy bỏ

POST /api/v1/stories/21/existing/archive
{
  "storyId": 21,
  "reason": "Nội dung vi phạm an toàn gia đình."
}
Hoạt động phía Backend: Cập nhật StoryStatus = Archived. Câu chuyện bị ẩn khỏi danh sách đang xử lý.

4. Giai đoạn hội tụ chung (Phase 3 Học liệu ➔ Phase 4 Review ➔ Phase 5 Media)

Bất kể câu chuyện được tạo từ Luồng A (AI sáng tác) hay Luồng B (Tải truyện có sẵn), sau khi phiên bản truyện đã được chốt, hệ thống đều hội tụ vào cùng một quy trình xử lý duy nhất.

Bước C1: Polling theo dõi tiến trình sinh học liệu ngầm (Phase 3) GET /api/v1/stories/{storyId}/generation/progress
Hoạt động phía Backend (Chuỗi xử lý ngầm): Hệ thống Worker ngầm chạy tuần tự 3 công việc (Jobs):
1. GenerateVocabulary: AI trích xuất 5 từ vựng tiêu biểu trong câu chuyện kèm giải nghĩa thân thiện cho trẻ ➔ Lưu bảng story_vocabulary.
2. GenerateQuiz: AI sinh 3 câu hỏi trắc nghiệm kiểm tra độ ghi nhớ ➔ Lưu bảng quiz_items.
3. GenerateDiscussion: AI sinh 3-4 câu hỏi gợi mở thảo luận bài học đạo đức ➔ Lưu bảng discussion_questions.
Khi hoàn thành cả 3 job, Backend tự động chuyển trạng thái truyện từ Draft sang ContentReview.

5. TypeScript API Client mẫu cho Frontend

const BASE_URL = import.meta.env.VITE_API_URL || 'http://localhost:5259';

export async function apiRequest<T>(endpoint: string, options: RequestInit = {}): Promise<T> {
  const token = localStorage.getItem('access_token');
  const isFormData = options.body instanceof FormData;
  
  const headers: Record<string, string> = {
    Accept: 'application/json',
    ...(isFormData ? {} : { 'Content-Type': 'application/json' }),
    ...(options.headers as Record<string, string>),
  };

  if (token) {
    headers['Authorization'] = `Bearer ${token}`;
  }

  const response = await fetch(`${BASE_URL}${endpoint}`, { ...options, headers });
  const envelope = await response.json();

  if (!response.ok || !envelope.success) {
    throw new Error(envelope.message || 'Thao tác thất bại');
  }

  return envelope.data as T;
}

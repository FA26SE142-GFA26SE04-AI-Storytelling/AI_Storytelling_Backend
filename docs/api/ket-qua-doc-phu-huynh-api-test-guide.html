API và test case — Kết quả đọc của bé (phía phụ huynh)

AI Storytelling Backend · tab "Kết quả đọc" của chủ hồ sơ: lọc ngày / chưa đọc xong, số lần đọc lại, chi tiết câu đố, đọc to, EXP + từ vựng, chế độ đọc, bản "Bé kể lại", tổng quan · mỗi API có giải thích, body mẫu và test case kèm đầu vào / kết quả mong đợi. Tích vào ô để đánh dấu đã chạy (lưu trong trình duyệt).

Quy ước chung

Cách gọi

  • Địa chỉ gốc: {host}/api/v1/ParentReadingFeedback. Phản hồi bọc trong ApiResponse: { "success", "message", "data", "errors" }. Danh sách bọc thêm PagedResult: items, pageIndex, pageSize, totalCount, totalPages, hasPreviousPage, hasNextPage.
  • Đính kèm Authorization: Bearer {accessToken}. Cả 3 API chỉ dành cho role User và chỉ chủ hồ sơ (OwnerUserId) mới xem được hồ sơ của bé.
  • Lỗi nghiệp vụ: { "success": false, "message": "…", "data": null }. Sai kiểu dữ liệu query (ví dụ From=abc): 400 "Dữ liệu đầu vào không hợp lệ." kèm errors. Sai role: 403 body rỗng; không token: 401; không phải chủ hồ sơ hoặc hồ sơ không tồn tại: 403 "Bạn không có quyền với hồ sơ trẻ này.".
  • Thời gian là UTC, định dạng ISO 2026-11-10T08:00:00Z. Khoảng lọc là [From, To): tính cả mốc From, không tính mốc To.
  • Enum trả dạng chuỗi: status ∈ Completed · Started · Reading · Activity · Abandoned · ForceExited; feeling ∈ VeryLike (Rất thích) · Like (Thích) · Neutral (Bình thường) · Dislike (Chưa thích); readingMode ∈ ListenFirst · ReadFirst.

Dữ liệu thật trong Database/Seed (nạp bằng Seed-Database.ps1)

  • Trước hết: áp migration AddReadingSessionReadingMode (thêm cột reading_sessions.ReadingMode), rồi chạy Database/Seed-Database.ps1. Không cần nạp SQL thêm: dữ liệu đọc của Bé An đã nằm trong seed, Task 0 chỉ kiểm tra lại.
  • Mật khẩu mọi tài khoản demo: Demo@123. Đăng nhập bằng POST /api/v1/Auth/login với { "identifier": "parent_demo1", "password": "Demo@123" }.
  • Tài khoản: parent_demo1 (User, Id 2) là chủ hồ sơ 1 = Bé An và 2 = Bé Bình; parent_demo2 (User, Id 3) là chủ hồ sơ 3 và 4 — dùng để thử "không phải chủ hồ sơ"; moderator_demo1 (Moderator) dùng thử sai role; token bé 1 lấy bằng POST /api/v1/ChildAccessCredential/easylogin/login với { "secret": "demo-qr-child-01" }.
  • Seed của Bé An (hồ sơ 1): phiên 1 (truyện 1 "Chú Thỏ Thông Minh - Bản 1", phiên bản 1, Completed, 10 trang, 600 giây, quiz câu 1 đúng), phiên 11 (truyện 21 "Cá heo tốt bụng", phiên bản 26, Completed, 360 giây), phiên 13 (truyện 16 "Chú mèo biết lắng nghe", phiên bản 21, Completed, 300 giây). Bé Bình (hồ sơ 2): phiên 2 (truyện 1, Reading, 3 trang, 200 giây). Seed có sẵn bản kể lại 1 gắn phiên 1 (không ghi âm, 1 cảnh đánh dấu: cảnh 1). Phiên bản 1 có 1 scene; phiên bản 21 và 26 không có scene (totalPages = 0). Từ vựng 1 = "thông minh", 2 = "dũng cảm".
  • Seed còn có cho Bé An (các dòng Id từ 101): câu quiz 101 (phiên bản 1, TrueFalse); phiên 101 (Completed, 5 ngày trước, 540 giây, VeryLike, ListenFirst), 102 (Completed, 30 giờ trước, 420 giây, Like, ReadFirst), 103 (Reading, mở 12 ngày trước, 30 giây), 104 (Reading, mở 1 ngày trước, truyện 16, 120 giây); các lần trả lời quiz 101–104; telemetry đọc to / EXP / từ vựng của phiên 101 và 102; bản kể lại 101 (không ghi âm, 1 cảnh). Bản kể lại trong seed đều không ghi âm vì API ParentStorySummary phải ký link cho file ghi âm, file không có thật sẽ làm API đó lỗi.
  • Phần tính theo ngày giờ hiện tại (seed dùng NOW()): các giá trị động <FROM_7D>, <TO_PLUS_1D>, <COMPLETED_AT_101> ở khung dưới phải nhập lại theo ngày bạn chạy test (có câu SQL lấy sẵn ở mục mô tả từng giá trị).
  • Lưu ý: test làm đổi dữ liệu (các test "SQL" sửa phiên / telemetry / bản kể lại). Mỗi Task bắt đầu từ DB vừa seed; chạy theo thứ tự trên trang. Test có nhãn "(SQL)" cần hoàn tác bằng câu SQL kèm theo trước khi sang test kế tiếp.

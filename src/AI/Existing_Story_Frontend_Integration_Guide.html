Lưu ý trước khi tích hợp

Backend Luồng 2 phải được triển khai trước. Tại thời điểm tạo tài liệu, working tree đang ở main và chưa chứa ExistingStoriesController. Hợp đồng dưới đây được đối chiếu từ commit 436da8b. Nếu gọi endpoint import trên backend chưa có commit này, frontend sẽ nhận 404.
Điểm dễ bỏ sót nhất POST /evaluate chỉ đánh giá và trả quyết định, không tự queue học liệu. Nếu truyện import được đánh giá Suitable, frontend phải gọi keep-original để bắt đầu Vocabulary → Quiz → Discussion.

1. Luồng tổng thể

Bước 1Chọn nguồn truyện
Bước 2Creative Input / Import
Bước 3Guardrail / Evaluate
Bước 4Outline / Adapt
Bước 5Content & học liệu
Bước 6Review → Media → Ready

Ba quyết định dưới đây áp dụng riêng cho nhánh truyện do người dùng nhập hoặc tải lên:

Suitable

Hiển thị “Dùng bản gốc”, gọi keep-original, sau đó chuyển sang màn hình tiến độ.

AdaptRecommended

Cho chọn AI Adapt, chỉnh tay, giữ nguyên có lý do, hoặc lưu trữ.

Blocked

Không cho giữ nguyên, adapt hay queue học liệu. Chỉ hiển thị lý do và hành động archive.

3. Quy ước API chung

Mọi request được bảo vệ phải gửi JWT access token:

Authorization: Bearer <accessToken>
Content-Type: application/json

Response thành công và thất bại đều dùng envelope:

{
  "success": true,
  "message": "Thao tác thành công.",
  "data": {},
  "errors": null
}
Frontend phải kiểm tra cả HTTP status và success. Không đọc payload nghiệp vụ trực tiếp từ response root; dữ liệu luôn nằm trong data.

Điều kiện dùng hai luồng:

  • Người dùng đăng nhập với role Parent hoặc Teacher.
  • Child Profile đang ở trạng thái Active.
  • Người dùng có quyền GenerateStory trên Child Profile.
  • Nội dung import không vượt 20.000 từ.

6. Luồng A — Tạo câu chuyện bằng AI

6.1 Tải context trước khi render form

Dùng response để khóa đúng maximumLength, language, vocabulary level, character/setting mode và hiển thị policy. Không hard-code option nếu backend đã trả chúng.

6.3 Poll và review outline

GET /api/v1/stories/123/outline

Poll cho đến khi currentVersion có dữ liệu hoặc lastErrorCode xuất hiện. Tại OutlineReview, người dùng có thể:

  • Sửa trực tiếp bằng PUT .../outline/versions/{versionNo}.
  • Regenerate bằng một operationKey duy nhất, tối thiểu 8 ký tự.
  • Reject với lý do rõ ràng.
  • Approve bằng một approvalKey duy nhất, tối thiểu 8 ký tự.
POST /api/v1/stories/123/outline/versions/2/approve

{ "approvalKey": "approve-outline-123-v2" }

6.4 Sinh content và học liệu

Sau approve, backend chạy tuần tự:

GenerateContent → Safety/Quality → Vocabulary → Quiz → Discussion

Frontend dùng chung GET /api/v1/stories/{storyId}/generation/progress. Khác với Existing Story, trường content của luồng AI ban đầu sẽ ở trạng thái pending/processing rồi mới thành stable.

6.5 Hội tụ vào Review và Media

Khi isComplete là true, chuyển sang các bước Review → Validation → Approve → Media giống mục 7.5 và 7.6 bên dưới.

7. Luồng B — Người dùng nhập hoặc tải truyện có sẵn

TXT không được upload dạng multipart. Frontend đọc tệp TXT dưới dạng UTF-8 bằng File.text(), đưa chuỗi vào trường content, đặt inputMethod: "txt", rồi gửi JSON giống thao tác paste.

Render hai nhóm lỗi riêng:

  • profileFitIssues: chưa phù hợp độ tuổi/độ khó, có thể adapt hoặc sửa tay.

7.3 Xử lý theo quyết định

decisionTextUI được phépAPI tiếp theo
SuitableDùng bản gốc hoặc archive.keep-original để queue artifact.
AdaptRecommendedAI Adapt, sửa tay, giữ nguyên nếu canKeepOriginal, hoặc archive.adapt, content, keep-original hoặc archive.
BlockedChỉ xem lỗi cứng và archive.archive.

AI Adapt:

POST /api/v1/stories/123/existing/adapt

{
  "storyId": 123,
  "baseStoryVersionId": 456,
  "guideline": "Rút gọn câu và dùng từ phù hợp trẻ 6-8 tuổi."
}

Response trả version mới và decision sau khi backend tự evaluate. Nếu decision là Suitable, backend đã queue artifact; chuyển thẳng sang polling.

Sửa tay:

PUT /api/v1/stories/123/existing/content

{
  "storyId": 123,
  "baseStoryVersionId": 456,
  "title": "Lan và khu rừng",
  "content": "Nội dung đã chỉnh...",
  "lesson": "Biết giúp đỡ bạn bè."
}

Luôn thay baseStoryVersionId bằng version mới nhất. Nếu nhận STALE_BASE_VERSION, tải lại dữ liệu và yêu cầu người dùng đối chiếu trước khi gửi lại.

Giữ bản hiện tại và bắt đầu sinh học liệu:

POST /api/v1/stories/123/existing/keep-original

{
  "storyId": 123,
  "storyVersionId": 456,
  "overrideReason": "Nội dung đã phù hợp và được phụ huynh xác nhận."
}
Không gọi keep-original khi Blocked. Chỉ render nút khi canKeepOriginal === true. Frontend phải giữ guard này ngay cả khi backend có thêm validation sau này.

8. API client mẫu

lib/api.ts
const API_URL = import.meta.env.VITE_CORE_API_URL;

export class ApiError extends Error {
  constructor(
    public status: number,
    message: string,
    public errors: string[] = [],
    public data: unknown | null = null,
  ) { super(message); }
}

export async function api<T>(
  path: string,
  init: RequestInit = {},
): Promise<T> {
  const accessToken = authStore.getState().accessToken;
  const response = await fetch(`${API_URL}${path}`, {
    ...init,
    headers: {
      'Content-Type': 'application/json',
      ...(accessToken ? { Authorization: `Bearer ${accessToken}` } : {}),
      ...init.headers,
    },
  });

  const envelope = await response.json() as ApiResponse<T>;
  if (!response.ok || !envelope.success || envelope.data === null) {
    throw new ApiError(
      response.status,
      envelope.message,
      envelope.errors ?? [],
      envelope.data,
    );
  }
  return envelope.data;
}

9. State machine phía Frontend

type ExistingStoryUiState =
  | { step: 'editing-import' }
  | { step: 'evaluating'; storyId: number; versionId: number }
  | { step: 'decision'; result: ExistingStoryEvaluation }
  | { step: 'mutating'; action: 'adapt' | 'manual' | 'keep' | 'archive' }
  | { step: 'generating'; storyId: number }
  | { step: 'review'; storyId: number }
  | { step: 'media'; storyId: number }
  | { step: 'ready'; storyId: number }
  | { step: 'failed'; message: string; retryable: boolean };

type AIStoryUiState =
  | { step: 'creative-input' }
  | { step: 'checking-input'; storyId: number; requestId: number }
  | { step: 'outline'; storyId: number; versionNo?: number }
  | { step: 'generating'; storyId: number }
  | { step: 'review'; storyId: number }
  | { step: 'media'; storyId: number }
  | { step: 'ready'; storyId: number }
  | { step: 'failed'; message: string; retryable: boolean };

function nextAfterEvaluation(result: ExistingStoryEvaluation) {
  switch (result.decisionText) {
    case 'Suitable':
      return { showKeepOriginal: true, showEdit: false, showArchive: true };
    case 'AdaptRecommended':
      return {
        showKeepOriginal: result.canKeepOriginal,
        showEdit: true,
        showArchive: true,
      };
    case 'Blocked':
      return { showKeepOriginal: false, showEdit: false, showArchive: true };
  }
}

Không suy ra trạng thái chỉ từ URL hay local state. Sau refresh trang, khôi phục bằng IDs đã lưu và gọi GET evaluation/progress/review tương ứng.

  • Dùng AbortController để hủy evaluate/adapt khi rời trang.
  • Không tự retry mutation POST/PUT nếu không có idempotency key.
  • Khi sửa/adapt thành công, thay version cũ bằng storyVersionId mới từ response.
  • Không dùng endpoint publish chung cho Existing Story; phải đi qua Review → Approve → Media → Ready.

11. Checklist nghiệm thu Frontend

  • JWT được gửi cho mọi endpoint AI Input, Outline, Existing Story, Generation, Review và Media.
  • Form AI lấy option và giới hạn từ Context API trước khi submit.
  • AI input xử lý đúng các HTTP 202, 409, 422 và 503.
  • Outline edit/regenerate luôn dùng version hiện tại và operation key mới.
  • Chỉ queue GenerateContent sau khi người dùng approve outline.
  • Import retry dùng lại cùng idempotencyKey.
  • Frontend lưu cả storyId và version ID hiện tại.
  • UI rẽ nhánh bằng decisionText và tôn trọng canKeepOriginal.
  • Suitable gọi keep-original trước khi bắt đầu polling.
  • Blocked không thể gọi keep/adapt/manual edit từ UI.
  • Polling dừng khi complete/error và được hủy lúc unmount.
  • Review luôn dùng versionId mới nhất.
  • Approve chỉ bật khi validation trả canApprove: true.
  • Chỉ mở trang đọc khi media trả isReady: true.
  • Đã test 400, 401, 403, 404, 409, 500 và double-click submit.
  • Đã test reload trình duyệt ở màn hình decision, generation, review và media.

1. Chuẩn bị và quy ước

  • Chạy API (Swagger hoặc Postman). Đặt biến BASE = địa chỉ API, ví dụ https://localhost:5001.
  • Cần hai loại token khác nhau: PARENT_TOKEN (đăng nhập tài khoản phụ huynh, role User) và CHILD_TOKEN (token của trẻ, lấy ở bước handover). Token của trẻ không gọi được API phụ huynh và ngược lại.
  • Mọi response có dạng { "success": ..., "data": ..., "message": ... }. Lỗi nghiệp vụ trả mã 400/403/404/409 kèm message.
  • Database cần đã áp migration AddStorySummaryQuestionDetails theo thao tác được phê duyệt trước khi chạy API mới. Trang này không tự áp migration hay seed.
  • Kho lưu trữ (Supabase Storage) phải được cấu hình, vì ghi âm được upload lên đó.
Dữ liệu seed đã đối chiếu từ SQL, chưa truy vấn database: parent_demo1 (mật khẩu demo Demo@123) sở hữu hồ sơ 1 = Bé An. Nguồn: 15_story_scenes.sql, 16_illustration_beats.sql, 19_media_assets.sql. Phiên 103 của Bé An đang Reading, chưa có bản tóm tắt nên dùng cho TC-Q01. Phiên 2 thuộc Bé Bình, dùng kiểm 404 khi gọi bằng token Bé An.
Seed có bản tóm tắt 1 (phiên 1) và 101 (phiên 101), mỗi bản có một câu hỏi cũ về cả cảnh 1, không ghi âm/chữ và chưa trả lời. Đây là dữ liệu hợp lệ, không chuyển thành câu hỏi theo tranh. 2. Sơ đồ thứ tự gọi API

Đi từ trên xuống. Ô viền xanh lam gọi bằng token phụ huynh, ô viền tím gọi bằng token của trẻ. Hai API gửi của trẻ (2a, 2b) không cần theo thứ tự với nhau.

3. Bước 0: tạo dữ liệu nền

Làm tuần tự. Mọi request trừ 0.1 đều cần header Authorization: Bearer PARENT_TOKEN.

POST0.1 Đăng nhập phụ huynh A không cần token

POST {BASE}/api/v1/Auth/login
{
  "identifier": "email-hoac-username-cua-A",
  "password": "mat-khau-cua-A"
}

Lưu data.accessToken → PARENT_TOKEN và data.refreshToken → REFRESH. Làm tương tự để có token của tài khoản B.

POST0.2 Tạo hồ sơ trẻ

POST {BASE}/api/v1/ChildProfile
{ "nickname": "Bé Bin", "ageBand": "Age_6_8", "language": "vi" }

Lưu data.id → CHILD_ID. Tạo thêm hồ sơ CON2 với nickname khác để test phiên đọc của trẻ khác.

POST0.3 Learning Profile

POST {BASE}/api/v1/LearningProfile/{CHILD_ID}
{
  "readingLevel": 2,
  "readingMode": "ListenFirst",
  "comprehensionGoal": "Kể lại được ý chính",
  "topics": [ { "topic": "Động vật", "relation": "FavoriteTopic" } ]
}

POST0.4 Safety Policy: ghi nhận consent và bật giọng nói

POST {BASE}/api/v1/SafetyPolicy/{CHILD_ID}
{
  "maxStoryLength": 2000,
  "parentalGateEnabled": true,
  "consentRecorded": true,
  "voiceAnswersEnabled": true,
  "voiceConsentAccepted": true,
  "categories": []
}
voiceAnswersEnabled: true là điều kiện để trẻ ghi âm được (TC-R02 kiểm tra trường hợp tắt). Để test TC-R02, gọi lại PUT /api/v1/SafetyPolicy/{CHILD_ID} với "voiceAnswersEnabled": false, test xong bật lại.

PATCH0.5 Kích hoạt hồ sơ

PATCH {BASE}/api/v1/ChildProfile/{CHILD_ID}/activate

Kết quả mong đợi: 200, status = "Active". Nếu 400 là còn thiếu Learning Profile hoặc consent.

0.6 Chuẩn bị truyện Ready của CON1

Cần một truyện trạng thái Ready bé được phép đọc. Để test câu hỏi thứ 6, cần fixture riêng có ít nhất 6 tranh/cảnh đủ điều kiện và khác nhau trong cùng phiên. Hai cách chuẩn bị truyện:

  • Tạo bằng luồng AI hoặc soạn tay rồi duyệt nội dung và xác nhận media (xem docs/API_FRONTEND_ACTOR_FLOWS.md mục 6, 7).
  • Hoặc dùng truyện đã seed (Database/Seed/11_stories.sql) sau khi chạy Seed-Database.ps1; kiểm tra truyện đó thuộc đúng hồ sơ trẻ bạn dùng.
Seed truyện 1 có 1 cảnh và 1 tranh theo beat, đủ TC-Q01/Q04/Q05 nhưng không đủ TC-Q14 (câu thứ 6). Ca không có tranh và ca nhiều tranh dùng fixture riêng qua các luồng ứng dụng hiện có; không tự sửa seed hay chạy SQL ghi để tạo fixture.

GET0.6b Kiểm tra bé được phép đọc truyện (tùy chọn)

GET {BASE}/api/v1/ChildAccessCredential/story-handover?storyId={STORY_ID}

{ "storyId": STORY_ID, "supervisorRefreshToken": "REFRESH" }

Lưu data.accessToken → CHILD_TOKEN. Từ bước này dùng CHILD_TOKEN cho API trẻ.

Lưu data.sessionId → SESSION_ID.

Lấy data.scenes[].sceneId và data.scenes[].illustrations[].beatOrder để gửi đúng câu hỏi. Có thể gọi thêm POST .../sessions/{SESSION_ID}/complete để phiên ở trạng thái Completed; API tóm tắt dùng được cả khi đang đọc lẫn khi đã xong.

4. API 1: Trẻ gửi ghi âm CHILD_TOKEN

POST/api/v1/child/reading/sessions/{sessionId}/summary/recording

Body: multipart/form-data, một field tên audio (webm, ogg, wav, mp3, m4a hoặc flac), tối đa 3 000 000 byte.

# curl mẫu
curl -X POST "{BASE}/api/v1/child/reading/sessions/{SESSION_ID}/summary/recording" \
  -H "Authorization: Bearer CHILD_TOKEN" \
  -F "audio=@tom-tat.webm;type=audio/webm"

Response thành công:

{ "success": true, "message": "Đã gửi cho bố mẹ", "data": { "summaryId": 1, "message": "Đã gửi cho bố mẹ" } }

Trong Swagger: chọn Try it out, chọn file ở ô audio. Nếu chưa có file thật, ghi âm bất kỳ 5 giây bằng điện thoại và đổi đuôi phù hợp.

5. API 2: Trẻ gửi từng câu hỏi về tranh CHILD_TOKEN

POST/api/v1/child/reading/sessions/{sessionId}/summary/questions

multipart/form-data: sceneId bắt buộc; beatOrder là thứ tự tranh từ scenes[].illustrations[].beatOrder; text và file audio đều tùy chọn. Khi có tranh theo beat thì phải chọn đúng tranh. Không có tranh theo beat thì để trống beatOrder, hỏi về cả cảnh; nếu có ảnh minh họa cả cảnh, hệ thống nhớ đúng ảnh đó.

Mỗi tranh một câu hỏi, tối đa 5 câu trong phiên; từng lần gửi thành công đều thông báo bố mẹ. Chữ được trim, rỗng thành null, tối đa 200 ký tự. Audio tối đa 3 000 000 byte, các định dạng như bản kể lại; chỉ cần bật giọng nói khi gửi audio. Không dùng AI để đọc/chấm câu hỏi.

curl -X POST "{BASE}/api/v1/child/reading/sessions/103/summary/questions" \
  -H "Authorization: Bearer CHILD_TOKEN" \
  -F "sceneId=1" -F "beatOrder=1" -F "text=Sao bạn thỏ buồn?"

# Tùy chọn thêm ghi âm vào request trên:
# -F "audio=@cau-hoi.webm;type=audio/webm"
{ "success": true, "message": "Đã gửi cho bố mẹ", "data": { "summaryId": 102, "questionId": 102, "message": "Đã gửi cho bố mẹ" } }

Id 102 chỉ là giá trị dự kiến khi TC-Q01 là lần tạo đầu tiên sau seed. Lưu data.summaryId và data.questionId thực tế để gọi API đánh dấu đã trả lời. Các bản tóm tắt cũ vẫn dùng tên trường flags ở API bố mẹ.

6. API 3: Phụ huynh xem danh sách PARENT_TOKEN

GET/api/v1/ParentStorySummary/{childProfileId}?pageIndex=1&pageSize=20

Chỉ chủ hồ sơ. Mới nhất trước. pageSize tối đa 50. flags giữ tên cũ nhưng mỗi phần tử là một câu hỏi; sắp theo cảnh rồi thứ tự tranh. Mỗi item có unansweredCount là số câu chưa được bố mẹ đánh dấu đã trả lời.

{
  "success": true,
  "data": {
    "items": [{
      "summaryId": 102, "sessionId": 103, "storyId": 1, "title": "...",
      "createdAt": "2026-11-16T10:00:00Z",
      "recordingUrl": null, "recordingSentAt": null,
      "flagsSentAt": "2026-11-16T10:00:00Z", "unansweredCount": 1,
      "flags": [{
        "questionId": 102, "sceneId": 1, "sceneIndex": 0, "sceneText": "...",
        "beatOrder": 1, "pictureText": "...",
        "illustrationUrl": "https://...signed-picture...",
        "questionText": "Sao bạn thỏ buồn?", "questionAudioUrl": null,
        "askedAt": "2026-11-16T10:00:00Z", "answeredAt": null
      }]
    }],
    "totalCount": 3, "pageIndex": 1, "pageSize": 20
  }
}

Mẫu trên trích item mới sau TC-Q01, khi seed ban đầu có 2 bản và chưa xóa gì; thời gian/title/link là minh họa. Trước TC-Q01, GET /api/v1/ParentStorySummary/1 có tổng 2 bản (101 và 1), mỗi bản unansweredCount=1; các dòng cũ có questionId lần lượt 101 và 1, beatOrder=null, pictureText=null, questionText=null, questionAudioUrl=null, answeredAt=null.

7. API 4: Phụ huynh đánh dấu đã trả lời PARENT_TOKEN

PUT/api/v1/ParentStorySummary/{childProfileId}/{summaryId}/questions/{questionId}/answered

Bố mẹ giải thích cho bé ngoài app; API chỉ lưu hoặc bỏ dấu đã trả lời. Gửi JSON { "answered": true } hoặc { "answered": false }. Chỉ chủ hồ sơ, câu hỏi phải thuộc đúng bản tóm tắt của bé. Không gửi thông báo cho bé.
